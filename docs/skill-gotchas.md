# Skill gotchas

One line per gotcha: the reference file it belongs in, then the fact.

- references/emulator-qa.md (§emu.py, PPSSPP): `emu.py --mash` is ignored for PSP: psp.py never reads MASH, so a mashed route just idles. This repo uses `tools/debug/drive.py --mash circle`.
- references/emulator-qa.md (§Debug tool, PPSSPP): `memory.breakpoint.add {write: true}` never stopped PPSSPPHeadless qa-1 on a store the game makes (savedata param dataBuf); RAM diffs and cheat databases found the fields instead.
- references/emulator-qa.md (§Debug tool): CWCheat codes from a real PSP can address a heap object at a different base than PPSSPP (here 0x08EC0000 on PSP vs 0x09EC0000 in PPSSPP, +0x01000000); find the object by a known field and keep the cheat's offsets.
- references/platform-psp.md (save data): PPSSPP stores sceUtility savedata encrypted when the game asks for it; edit the plaintext copy in RAM and let the game save, rather than the .SAV file.
- references/emulator-qa.md (§emu.py): context-mode trims Read/Bash output of skill reference files and disassembly above ~4 KB even in the main thread; read with offset/limit.
- references/platform-psp.md (save data): PPSSPP's sceUtility save dialog asks "overwrite the data?" with Yes/No side by side and the cursor on No when a save already exists (e.g. the one created at first boot); a route must press left before circle, or the save silently doesn't happen.
- scripts/disasm.py / capstone (references/platform-psp.md): capstone's MIPS disasm stops at the first undecodable word; ad-hoc scans of a PSP RAM image need md.skipdata = True or they silently cover only the first few KB.
- references/emulator-qa.md (§Debug tool): a guided in-game tutorial (here the first Communication-mode Hexcite match) can ignore RAM pokes and hang; check whether the same minigame has an unguided mode (Free Mode) for forced-result warps.
- references/emulator-qa.md (§Debug tool): faster than solving a guided tutorial by eye: find the scene-switch function's callers (jal xrefs + the a1/a2 immediates), read the case that enters the tutorial, and poke its "seen" bit (here one bit at SM+0xAA); a scene jump table indexed by scene id then maps every remaining screen (credits, game over) in an hour.
- references/emulator-qa.md (§Debug tool): poking only the scene-request field (no fade/arg fields) switches scenes cleanly from an idle menu, but the previous screen's overlay can stay drawn over the next script; shoot scripts from script warps instead.
- scripts/psp.py (references/emulator-qa.md §emu.py, PPSSPP): the docstring says each run gets a fresh OUT/memstick, but Run() never clears it, so a re-run into the same OUT boots with the previous run's saves (here New game became Continue and a warp landed on the wrong scene); clear OUT/memstick when memstick is None. Worked around in tools/debug/warp.py.
- scripts/ (scratch disasm): a helper named `dis.py` shadows the stdlib `dis` that capstone imports (circular import error); name scratch scripts something else.
- references/pipeline.md (Identity): PETA nested archives used 16-byte file alignment vs 2048 in the outer one; derive alignment per archive from the identity test, not one constant.
- references/platform-psp.md (EBOOT dump): PPSSPPHeadless (qa-1) ignores memstick/PSP/SYSTEM/ppsspp.ini, so `DumpFileTypes = 7` dumps nothing headless; run the GUI PPSSPPWindows64.exe with the ini set (this repo: tools/dump_eboot.py, ~10 s).
- references/pipeline.md (§Extract, PSP): the EBOOT carries name-substitution tokens (主人公の名前) the renderer strncmp()s and kinsoku tables in .rodata; jpscan-style filters list them as text. Restrict scans to .rodata/.data via section headers (the PRX dump keeps them) to drop .text noise.
- references/platform-psp.md (containers): a game's LZ decoder may copy each back-reference with memcpy (here YKLZ, 0x088ACA48), so a match whose length exceeds its displacement (overlapping its own output) decodes wrong in game while a byte-by-byte Python decoder accepts it. A repacked font lost every pixel equal to the one 2 or 18 bytes before; SOS text could lose repeated runs too. Check the original streams for overlap (here 0 of 2375) and make the packer never emit it; test with a strict decoder.
- references/platform-psp.md (EBOOT): re-signing works with sign_np -elf (github.com/swarzesherz/sign_np, needs gcc + zlib; built under WSL here), tag = the original's ~PSP tag at +0xD0. PPSSPP's dumped ELF carries decrypt-buffer junk past the ~PSP header's elf_size (+0x28); cut it before signing.
- references/platform-psp.md (EBOOT): new code in a relocatable PRX needs new relocation entries for every absolute word (jal, lui/lo pairs); they can be appended to the end of the last 0x700000A0 block (grow that section and the segment, shift the later sections and e_shoff).
- references/translation.md (§Batch design) / SKILL.md ground rules: context-mode also trims Bash *output* over ~4 KB to a stub (not only whole-file Reads); keep shell output small or print via ctx_execute.
- references/emulator-qa.md (§Visual QA): `qa_gate.py init --glob "*.png"` on a PPSSPP warp tour also picks up each run's memstick/PSP/SAVEDATA/*/ICON0.PNG + PIC1.PNG (144 rows for 48 shots); delete the memstick dirs (or narrow the glob) before init.
- references/emulator-qa.md (§Debug tool): an `until mode:scene` poll every 20 frames can miss a short-lived scene (a level-up banner) on a build whose text timing differs, and the mash then walks into another menu; wait for the scene that lasts (here 5:48, not 5:47).
- references/emulator-qa.md (§Text coverage, PSP): PPSSPP's WebSocket `cpu.breakpoint.add` with `enabled:false, log:true, logFormat:"TXT {a1} {a1:s}"` logs every call without stopping (`:s` prints the string at a1, newlines included); PPSSPPHeadless prints it only with `-l --loglevel=1` (plain `-l` = debug level, ~27 MB per 900 frames). That is the PSP textcover log source (tools/debug/cover.py here).
- references/graphics.md (§Lettering): a staff-roll card that slides while shown can be cut by the screen edge though it fits its texture; measure its screen x over the whole display (shots at an interval that isn't a multiple of the card time drift through the slide) and cap the English at max(visible room, the Japanese ink width).
- references/emulator-qa.md (§Text coverage): a text-box-setter hook misses help bars drawn straight by a draw-text call each frame (PSP: Free Mode help, jal 0x08819270 with t3 = string); find those call sites (`mips.py calls`) and hook each one too, or textcover reports strings the screen clearly shows as never shown.
- references/emulator-qa.md (§Text coverage): text picked by a random/conditional chooser (idle comments, per-result reactions) is reachable by poking the chooser's final `move aN, sM` into `addiu aN, zero, K` (PPSSPP re-JITs poked code); one short run per K from a saved state covers a 98-entry table in ~10 min.
- references/emulator-qa.md (§emu.py, PSP): one PPSSPPHeadless WebSocket run step of 3600 frames times out the socket (TimeoutError in psp.recv); split long waits into <= 600-frame steps.
- references/emulator-qa.md (§Debug tool): a poke-jumped ending keeps the previous screen's overlay over its cards (The End? hidden behind the hub menu); set turns to one short of the limit and play one real turn so the game reaches the ending itself.
- references/emulator-qa.md (§Visual QA, Windows): never leave your shell's cwd inside a shot dir a background job will `rm -rf` ("Device or resource busy" fails the job); pass paths to sheet.py instead of cd.
- scripts/psp.py (Run): no load_state; `r.ws.call('game.state.load', path=..., wait=True)` then reset `r.base` from cpu.status works for poke brute-force loops in one process, but after ~100 reloads PPSSPPHeadless dropped the socket (ConnectionResetError): restart the Drive on OSError.
- references/emulator-qa.md (§Debug tool): to find a "use special / ability" gate, grep the pad-check helper's call sites for the button index (here `jal 0x0881B820` + `addiu a0, zero, 0xF` = square) and read the branch conditions; a 1-valued RAM brute force missed it because the flag's "ready" value was 0 (default -1).
- references/emulator-qa.md (§Debug tool): a puzzle-like guided tutorial ("place a piece on this line") whose target sits on a lattice parity the d-pad can't reach (cursor moves 2 columns per press) looked unsolvable by hand; RAM-diff the held piece's screen position (left/right/down x1 and x2), poke it, and brute rotations x positions in parallel processes, scoring hits by the score digits changing.
- references/emulator-qa.md (§Savestates): a state saved on an older build replayed a guided tutorial differently on the new ISO (a tutorial panel never appeared and the flow skipped ahead); re-warp from a cold boot on the current build before calling a missing screen a bug.
- references/translation.md (§Review, story pass): a fix round (fix008) that stripped `~` from non-Mikako lines also flattened 38 of Mikako's own ～ tails into "..." (all SC0 chapter ends + her EBOOT reactions); every story reviewer flagged it as Important. After a global style fix, diff the speaker the rule exempts (JP has the mark, EN lost it) before the story pass. EBOOT rows have no speaker column, so a speaker-keyed lint needs an id allowlist (batches.MIKAKO_VOICE).
- references/translation.md (§Review, story pass): story reviewers (~1k-line chapter, 5-8 parallel) took 40-115 s each and returned ~20 Minors per chapter; one more read-only reviewer on a diff file of every changed row (`>> id | spk | JP` / OLD / NEW) caught 10 regressions in the ~300 polish edits (an added word, a gender reveal, an abbreviation against the glossary). Cheap; do it before marking chapters `fixed`.
- references/pipeline.md (§Release, PSP): jp_left on the whole ISO is noise (GIMs, audio); scan what the build writes instead: each built SOS and the plain pre-sign EBOOT with `--slots` = the shown-text slot offsets (tools/release.py).
- references/platform-psp.md (EBOOT signing): sign_np via WSL failed mid-release with `Wsl/Service/CreateInstance/CreateVm/HCS/ERROR_NO_SYSTEM_RESOURCES` (13 GB RAM free, `wsl --shutdown` didn't help), failing the tests that rebuild the ISO; tools/sign.py now caches the signed EBOOT by the input ELF's sha1 (work/sign/cache), so an unchanged EBOOT needs no WSL. Cache the signer output from the start.
- references/pipeline.md (§Release): build the xdelta with `-S none` (no djw/lzma secondary compressor, which web patchers such as RomPatcher.js can't decode) and verify with the decode command the README gives (no -B); a disc patch here: 830 MB ISO -> 7.4 MB with `-B <iso size>` (6.8 MB with djw).
- SKILL.md (ground rules): the guard also blocks a quoted heredoc that pipes Python (`python - <<'PY'`); and a long `cat >> f <<'EOF'` of TSV rows with apostrophes failed in Git Bash ("unexpected EOF") through the tool: write fix TSVs with the Write tool.
